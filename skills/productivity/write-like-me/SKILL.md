# Write like me

## Quick start

Rewrite the user’s text so it reads like a credible human wrote it: plain, direct, slightly informal when fitting. **Default output: only the rewritten text**—no meta-commentary unless asked.

## When to apply

Triggers include: “less AI”, “un-AI”, “write like me”, “more natural”, “sound human”, “less corporate”, “my style”, “something I would send”.

## Style defaults (unless user specifies otherwise)

- Direct, practical, slightly informal—not sloppy  
- Clear opinions where appropriate; no fake enthusiasm  
- No long preambles, stiff apologies-as-templates, or emoji piles  
- Avoid generic AI / corporate wording (see [REFERENCE.md](REFERENCE.md))

## Rules

1. **Preserve intent** — Same facts, promises, commitments; if input is vague, stay vague; never invent detail.  
2. **Strip AI fingerprints** — Cut hollow balance, mirrored “not only X but also Y”, repetitive rhythms, generic caveats, buzzwords, recap paragraphs, forced optimism, excessive politeness, ornamental bullets.  
3. **Sound human** — Shorter sentences, plain English, specific words, natural transitions, occasional fragments, slight asymmetry, a touch of judgement where useful (e.g. “Technically we could, but I wouldn’t yet”).  
4. **Match context** — Tune for Slack/Teams, email, docs, personal note, or technical explanation (precision stays). Details: [REFERENCE.md](REFERENCE.md).  
5. **No fake mistakes** — No deliberate typos or random slang; contractions/informality only when natural.  
6. **Keep useful structure** — Retain bullets or sections when they help; don’t flatten into one blob or listify everything.  
7. **Dial back over-certainty** — Soften absolutes when advice (“should fix”, “I’d probably start with”) without weakening hard facts.  
8. **Modes** — If asked: **direct** (short/plain), **warmer**, **blunt**, **professional** (work-safe, no corp-speak), **slack**, **email**, **docs**. On request for options, give **direct / warmer / blunt** variants.

## Output

- Default: rewritten text only.  
- If user asks what changed: brief rationale afterward.  
- If user asks for options: three labeled variants (direct, warmer, blunt).
